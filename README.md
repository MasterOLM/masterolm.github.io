# masterolm.github.io

Статичный сайт-визитка (GitHub Pages, без сборки): `index.html` + `assets/`.

## Публикация

Опубликованный адрес: <https://obmenjson.ru/> (технический: <https://masterolm.github.io/>)

## Свой домен — где что лежит

- Домен `obmenjson.ru`, DNS у reg.ru (NS `ns1.reg.ru` / `ns2.reg.ru`):
  - апекс `@`: `A` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
  - `www`: `CNAME` → `masterolm.github.io`.
- В репозитории: файл [`CNAME`](./CNAME) с одной строкой `obmenjson.ru` — именно он привязывает домен
  к Pages при публикации из ветки.

Симптом «сайт открывается по `masterolm.github.io`, а по домену — `Site not found` (и сертификат `*.github.io`)»
означает, что домен не привязан к Pages: файла `CNAME` нет или он не в ветке `main`.

## Старый домен `masterolm.ru` — редирект через Cloudflare

`masterolm.ru` не обслуживает сайт, а только перенаправляет на `obmenjson.ru`. Реализовано в Cloudflare
(зона `masterolm.ru`, NS `kyree.ns.cloudflare.com` / `lila.ns.cloudflare.com`, делегирование в реестре .ru):

- DNS: `A @` и `A www` → `192.0.2.1` (заглушка RFC 5737), обе записи **Proxied** (оранжевая туча) —
  без прокси Redirect Rule не срабатывает, а отданный наружу `192.0.2.1` даёт таймаут соединения;
- Rules → Redirect Rules → `masterolm → obmenjson`: «All incoming requests»,
  Dynamic, Expression `concat("https://obmenjson.ru", http.request.uri.path)`, код **301**,
  Preserve query string — включён;
- SSL/TLS: режим Full, Edge Certificates → Always Use HTTPS включён; сертификат выпускает Cloudflare
  (Let's Encrypt, CN `masterolm.ru`).

Проверка: `curl.exe -sSI https://masterolm.ru/product.html` → `HTTP/1.1 301` и `Location: https://obmenjson.ru/product.html`.
Пока зона в статусе «Неверные серверы имен»/`Pending`, прокси не применяется — сначала нужно дождаться `Active`.
Парковка reg.ru (`95.163.244.138`) больше не используется; MX/TXT на домене не было, почту переносить не требовалось.

Ветка `main`, корень репозитория — Pages отдаёт файлы как есть. В Settings → Pages источник должен быть
`Deploy from a branch` → `main` → `/ (root)`. Сборка Jekyll отключена файлом `.nojekyll`.

## Если привязываете новый домен с нуля

1. В Settings → Pages → Custom domain вписать домен (например `example.ru`), сохранить.
2. У регистратора/в DNS:
   - для апекса (`example.ru`): `A` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - для `www`: `CNAME` → `masterolm.github.io`.
3. В репозиторий добавить файл `CNAME` с одной строкой — именем домена (без `https://` и без слэша).
4. Дождаться выпуска сертификата и включить `Enforce HTTPS`.

## Структура

- `index.html` — визитка: услуги, карточка продукта, контакты
- `product.html` — страница продукта «Обмен JSON» (что переносится, возможности, схема работы, скриншоты, видео, цены, требования, условия лицензии)
- `faq.html` — 27 вопросов и ответов (разметка `FAQPage` строится из текста страницы, см. ниже)
- `install.html` — руководство по установке и настройке (разделы 1–9, таблицы, `TechArticle`)
- `purchase.html` — «Как купить»: порядок работы, что нужно от клиента, документы, что не входит
- `terms.html` — публичная оферта (лицензионное соглашение): объём лицензии, запреты, оплата, обновления, ответственность, возврат
- `privacy.html` — политика обработки персональных данных (152-ФЗ)
- `404.html` — страница «не найдено»
- `assets/style.css` — общая тема; `assets/product.css` — продукт; `assets/legal.css` — юридические страницы и «Как купить»
- `assets/main.js` — переключатель RU/EN (язык в `localStorage`, принудительно — `?lang=en`)
- `assets/analytics.js` — Яндекс.Метрика и цели (см. раздел «SEO и аналитика»)
- `assets/product/*.png` — скриншоты для страницы продукта
- `favicon.svg`, `.nojekyll`, `.gitattributes`
- `tools/` — вспомогательные скрипты для правки контента (пересжатие скриншотов, генерация разметки FAQ); на публикацию не влияют

- Тексты — прямо в `index.html`, `product.html`, `purchase.html`; двуязычные блоки помечены классами `i18n-ru` / `i18n-en`
  (видимостью управляет атрибут `lang` на `<html>`). Юридические страницы (`terms.html`, `privacy.html`) — только на русском,
  в EN-режиме показывают пометку, что действует русская редакция.
- Заголовок вкладки на каждой странице свой: атрибуты `data-title-ru` / `data-title-en` на `<html>` (или `data-static-title`).
- Ссылки на видео — в блоке «Видео-демо» (`product.html`, ссылки YouTube и RuTube).
- Стили — `assets/style.css` (общая тема, переменные в `:root`, `--accent` — акцентный цвет), `assets/product.css`, `assets/legal.css`.

## SEO и аналитика

- **Канонические адреса.** Pages отдаёт и `/product`, и `/product.html` — это дубли. На каждой странице есть
  `<link rel="canonical">` на адрес с `.html` (главная — на `/`); новые страницы оформлять так же.
- **Микроразметка.** JSON-LD в `<head>`: главная — `Person`, `ProfessionalService`, `WebSite`;
  `product.html` — `SoftwareApplication` с `offers` (цены) и `BreadcrumbList`; `purchase.html` — `HowTo` и `BreadcrumbList`;
  `faq.html` — `FAQPage`; `install.html` — `TechArticle` и `BreadcrumbList`.
  При смене цен править `offers` в `product.html`, иначе разметка разойдётся с прайсом.
- **Яндекс.Метрика.** Номер счётчика — переменная `YM_ID` в начале `assets/analytics.js` (сейчас `113935350`).
  Подключение одно на все страницы, поэтому `<noscript>`-пиксель из стандартного кода не используется.
  Цели-события: `email_click` (клик по `mailto:`), `telegram_click`, `purchase_open`, `video_open`.
  В интерфейсе Метрики их надо создать как цели типа «JavaScript-событие» с такими же идентификаторами.
- **Вебмастеры.** В `index.html` есть закомментированные `yandex-verification` и `google-site-verification` — вставить коды
  из Яндекс.Вебмастера и Search Console, раскомментировать. После публикации отправить `https://obmenjson.ru/sitemap.xml`
  в оба вебмастера и запросить переобход страниц.
- **`robots.txt`.** `Clean-param: lang /` — чтобы `?lang=en` не считался отдельной страницей (директива Яндекса).
  Адреса вида `/product` дублями не закрываем: canonical уже указывает на `.html`-вариант.
- **`sitemap.xml`.** При правке содержимого страницы обновлять её `<lastmod>`.
- **Скриншоты.** Тяжёлые PNG пересжаты в палитровые PNG-8 (754 → 345 КБ суммарно) без изменения размеров, поэтому
  атрибуты `width`/`height` в `product.html` остались прежними. Новые скриншоты прогонять так:
  `powershell -NoProfile -File tools/png8.ps1 -Path <новый.png> -Out <out.png>` — перезаписывать оригинал,
  только если файл стал заметно меньше. Исходники до сжатия — в истории git (коммит со сжатием).

## Документация на сайте

`faq.html` и `install.html` — публичные версии документов из проекта 1С (`docs/faq.md`, `docs/install-guide.md`),
оформленные только по-русски (`data-static-title`, без переключателя RU/EN).

- `faq.html`: вопросы — заголовки `<h3 id="q-…">`, ответы — обычные абзацы/списки сразу после заголовка.
  Разметка `FAQPage` в `<head>` **генерируется из содержимого страницы**, чтобы вопросы и ответы не разошлись:
  `powershell -NoProfile -File tools/build-faq-ld.ps1 -Path faq.html` (скрипт удаляет прежний блок и вставляет новый;
  файл сохранён с BOM — так Windows PowerShell 5.1 читает в нём русский текст).
- `install.html`: структура повторяет руководство (разделы 1–9), таблицы обёрнуты в `<div class="table-wrap">`
  для горизонтальной прокрутки на мобильных. При правке нумерации разделов обновлять и ссылки вида
  `install.html#reglament` в `faq.html`.
- Тексты документов — источник истины в проекте 1С; при изменениях переносить правки и на сайт.
- Цены и стоимость поддержки в `faq.html` должны совпадать с прайсом в `product.html`.
